## 7. מה חסר — ומה קורה כש-LAND נכשל באמצע

**זו הפרצה הגדולה ביותר בשיטה. אין לה תשובה כרגע.**

LAND הוא `commit → push → אימות`. אם הוא נכשל באמצע, יש **ארבעה מצבים שונים** של
הריפו, וכל אחד דורש פעולה אחרת:

| נקודת הכשל | מצב הריפו | מי מחליט |
|---|---|---|
| **1. `git add` נכשל** | עץ מלוכלך, index ריק | אף אחד — פשוט חוזרים |
| **2. `git commit` נכשל** (hook, filename guard) | index מלא, HEAD לא זז | ⚠️ **RULE #5b:** אסור לרוץ `git commit` שוב על ניחוש. חובה `git log -1` קודם |
| **3. `git push` נדחה** (non-fast-forward) | commit מקומי, שרת מאחור | ⚠️ **זיכרון מתועד: "push rejected after a clean commit = PROJECT_STATE amend rewrote pushed history. Fix via reset --soft, not rebase/force"** — **החלטה שדורשת את עמיחי** |
| **4. CI נכשל אחרי push** | הכל בשרת, PR אדום | **עמיחי** — לתקן, להחזיר, או להשאיר |

**המסקנה: LAND חייב נקודת-עצירה מותנית.**
```
LAND:
  git add <שמות מפורשים>
  git diff --cached --name-only   → אמת מול הרשימה שאושרה ב-BUILD
  git commit
  git log -1                       → אמת שזז (RULE #5b)
  git push
  ┌─ הצליח → ls-remote + gh pr checks → דוח → סיום
  └─ נכשל  → ⚠️ עצור. הצג את המצב המדויק. אל תנסה תיקון. שאל.
```

**עוד שלושה חוסרים:**
1. **מה קורה כשהטסטים אדומים ב-BUILD.** `RULE #9`: *"STOP immediately · Do NOT try to
   fix by modifying tests · Report the exact failure"*. השיטה לא מזכירה זאת.
   *ראיה: זה קרה פעמיים בסשן והפרוטוקול עבד.*
2. **מי כותב את `INDEX.md`.** 34 שורות נוספו ידנית בכל סבב. אם LAND מאוחד — מתי?
3. **מה קורה כשהראיה סותרת את ההוראה בתוך LAND** (לא ב-GATE).
   *ראיה: סבב 30 — אבל שם זה היה GATE. בתוך LAND אין מנגנון.*
